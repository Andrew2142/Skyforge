A Claude Code Skill

Skyforge

Delegate your prompts across multiple AI agents

One chat in front of you; a manager dispatching your prompts to a pool of background agents behind it.

How it works

Skyforge runs multiple AI coding agents from one chat. You send tasks; a manager assigns each to a background worker, tracks them on a durable board, and reports back with one line when a task finishes. The agents work in parallel, so you can keep sending tasks without switching windows or watching a dashboard.

Three roles, each with one job. The manager is your main chat. It takes tasks in, dispatches them, and reports back, but it never writes code itself. Each worker is a background agent that owns a single task end to end and returns a structured report. The board is a JSON ledger in your repo at .skyforge/board.json, and it survives restarts, so you never lose state.

The whole thing is one loop. The first two steps wait for you; the rest run on their own.

  1. Send a task

    Say “skyforge” and describe the task. On first run it asks two toggles (auto mode and worktree isolation), then creates the board in the current repo.

  2. Approve, or skip

    Skyforge proposes a one-line breakdown (which tasks write files, which are read-only) and waits for your go-ahead. With auto mode on, it skips the prompt and dispatches immediately.

  3. Parallel dispatch

    Approved tasks launch as background workers and run in parallel. They’re held back only when they’d touch the same files, or each gets its own git worktree.

  4. Get the report

    Each worker returns a structured report; the board updates and you get a single line, not a wall of text.

  5. Check status

    Say “how’s the factory?” for a grouped status: what’s running, what’s blocked, what’s ready to review.

  6. Keep adding

    Queue new tasks anytime. Workers already running aren’t affected; the loop just widens to take more.

The board holds every task and its current state. One look shows what’s running, what’s done, and what’s blocked waiting on you.

queued·running·done·blocked·failed

Two workers can’t safely edit the same files at once. When you start Skyforge you pick one of two strategies for keeping their changes from colliding.

One more toggle. Auto mode sets whether the manager waits for your approval before dispatching, or just goes.

Installation

Skyforge is a Claude Code skill. Easiest install: point Claude Code (or any coding agent) at the repo and let it install for you.

Say this to your assistant Please install this skill:https://github.com/Andrew2142/Skyforge

It clones the repo and runs the installer for you. Or do it manually: 

curl -fsSL https://raw.githubusercontent.com/Andrew2142/Skyforge/main/install.sh | bash

The installer drops the skill in ~/.claude/skills/skyforge and its worker agent in ~/.claude/agents. Start a fresh session and it’s ready. Any of these triggers it, since it matches intent, not exact wording:

  • skyforge
  • delegate this to the team
  • spin up the factory
  • how’s the factory doing?
